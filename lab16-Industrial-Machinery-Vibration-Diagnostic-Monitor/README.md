# Лабораторна робота 16. Власна ідея, ч.2 (реалізація + метрики AI)

Автономний комплекс вібродіагностики промислового обладнання Industrial Machinery Vibration Diagnostic Monitor на базі мікроконтролера ESP32, триосьового акселерометра та сенсора температури MPU6050, дисплея SSD1306, накопичувача MicroSD, світлодіодного індикатора, аварійного зумера, Edge AI модуля TinyML для оцінки зносу агрегата та хмарної телеметрії ThingSpeak.

## Що робить система

- **Опитування вібраційного фону та температури:** Періодичне зчитування просторових прискорень та температури корпусу сенсором MPU6050 по шині I2C з усуненням постійної сили тяжіння.
- **Edge AI аналіз коливань TinyML:** Обробка вібраційного профілю у ковзному вікні, визначення середньоквадратичного фону RMS, дисперсії та високих гармонік для раннього виявлення механічних дефектів.
- **Оцінка деградації та прогнозування ресурсу:** Розрахунок індексу зносу агрегата від 0 до 100% на основі амплітуди коливань, розкиду сигналу та температури, а також визначення залишкового ресурсу RUL.
- **Трирівнева класифікація стану:** Автоматичне визначення режиму роботи: нормальний стан NORMAL, попередження WARNING та аварія CRITICAL при критичній вібрації або перегріві.
- **Локальна екранна візуалізація:** Відображення на дисплеї SSD1306 статусу агрегата, динамічної смужки навантаження, температури, зносу, ресурсу RUL та індикаторів зв'язку.
- **Оптична та звукова сигналізація:** Адаптивне керування світлодіодом за режимами роботи та ввімкнення модульованої сирени на зумері через апаратний LEDC при аварійній ситуації.
- **Автономне логування чорного ящика:** Запис телеметрії у файл generator_log.csv на картку MicroSD кожні 3 секунди з фіксацією позачергових міток при перевантаженні.
- **Хмарна телеметрія ThingSpeak:** Періодична відправка 6 діагностичних параметрів на хмарну платформу через REST API кожні 15 секунд.
- **Термінальна діагностика та дамп логу:** Виведення структурованої таблиці замірів у консоль та вивантаження вмісту файлу generator_log.csv за командою dump або log.

## Апаратна частина Wokwi

| Компонент | Підключення | Призначення |
|---|---|---|
| ESP32-DevKitC-V4 | — | Головний мікроконтролер системи |
| Сенсор MPU6050 | SDA GPIO 21, SCL GPIO 22, VCC 3.3V, GND | Вимірювання прискорень вібрації та температури агрегата |
| Дисплей SSD1306 | SDA GPIO 21, SCL GPIO 22, VCC 3.3V, GND | Відображення поточної телеметрії, параметрів та стану |
| Модуль картки MicroSD SPI | CS GPIO 5, SCK GPIO 18, DO GPIO 19, DI GPIO 23, VCC 3.3V, GND | Енергонезалежне збереження табличного журналу чорного ящика |
| Червоний світлодіод | GPIO 4 через резистор 220 Ом, катод GND | Оптична індикація нормального, попереджувального та аварійного станів |
| Резистор 220 Ом | Між GPIO 4 та анодом світлодіода | Струмообмежувальний захист лінії світлодіода |
| П'єзоелектричний зумер | GPIO 15 через апаратний LEDC таймер, другий контакт GND | Звукова сирена аварійного сповіщення персоналу |
| Макетна плата | — | Комутація ліній живлення 3.3V, землі та сигнальних провідників |

## Структура файлів

| Файл | Опис |
|---|---|
| `src/sketch.ino` | Основна логіка ESP32: збір сенсорів, дисплей, індикація, зумер, файлова система MicroSD, Wi-Fi, ThingSpeak та термінал |
| `src/ai_diagnostic.h` | Крайовий TinyML модуль: фільтрація коливань, розрахунок RMS, зносу, ресурсу RUL та класифікація станів |
| `diagram.json` | Схема підключення компонентів у симуляторі Wokwi |
| `generator_log.csv` | Приклад табличного журналу телеметрії на карті MicroSD |
| `platformio.ini` | Конфігурація проєкту для середовища PlatformIO |
| `libraries.txt` | Список залежностей та бібліотек для симулятора Wokwi |
| `wokwi.toml` | Файл налаштувань запуску симулятора Wokwi |

## Як запустити

1. Відкрити [симуляцію проєкту у Wokwi](https://wokwi.com/projects/476897292907447297) або запустити проєкт у середовищі PlatformIO.
2. Скомпілювати прошивку та завантажити її в мікроконтролер ESP32.
3. Відкрити Serial Monitor для спостереження за таблицею вимірювань та системними подіями.
4. Спостерігати за оновленням показників вібрації, температури та ресурсу на дисплеї SSD1306.
5. Для перевірки реакції системи змінити повзунки прискорення або температури на сенсорі MPU6050 у Wokwi.
6. Переконатися у переході системи у стан WARNING із блиманням індикатора та CRITICAL із увімкненням сирени й відправкою тривоги.
7. Надіслати команду `dump` або `log` у Serial Monitor для перегляду журналу `generator_log.csv` з картки пам'яті.
8. Перевірити оновлення 6 параметрів на дашборді хмарного сервісу ThingSpeak.
