# Лабораторна робота 18. Безпека медустанов (RFID + журнал + AI-аудит)

Інтелектуальний комплекс контролю доступу до режимних приміщень медичної установи Intelligent Healthcare Entry Sentinel на базі мікроконтролера ESP32, кнопок імітації карток RFID, сервоприводу дверного ригеля, символьного дисплея LCD 1602, світлодіодної індикації, звукового зумера, бортового модуля AI-аудиту доступу та хмарного журналу подій Blynk IoT.

## Що робить система

- **Ідентифікація пред'явника картки:** Неблокуюче опитування 3 кнопок карток чергового лікаря, медсестри денної зміни та невідомого ідентифікатора з програмним захистом від брязкоту контактів тривалістю 350 мілісекунд.
- **Керування робочими змінами:** Перемикання контексту роботи закладу між денною зміною DAY та нічним чергуванням NIGHT окремою кнопкою на макеті або віддалено з веб-панелі Blynk.
- **AI-аудит кожної спроби проходу:** Розрахунок індексу загрози від 0 до 100% за 4 факторами: базовий ризик ролі 5%, 15% або 75%, штраф невідповідності зміні до 60%, штраф 20% за повторні спроби частіше ніж раз на 2 секунди та штраф 15% за кожну попередню відмову поспіль.
- **Політики доступу та класифікація загроз:** Черговий лікар проходить цілодобово, медсестра допускається лише вдень, невідома картка завжди відхиляється, а кожна подія належить до 1 з 4 рівнів загрози NORMAL, LOW, ELEVATED або CRITICAL.
- **Захисне блокування термінала:** Після 3 відмов поспіль система переходить у режим LOCKOUT з ризиком 100%, не відчиняє двері для жодної картки протягом 15 секунд і самостійно знімає блокування після спливання таймера.
- **Керування дверним замком:** При дозволі сервопривід повертає ригель на 90 градусів і через 3 секунди автоматично повертає його у закрите положення 0 градусів.
- **Світлова та звукова індикація:** Зелений світлодіод підтверджує прохід, червоний сигналізує про відмову або блокування, а зумер через апаратний таймер LEDC подає короткі сигнали 2000 Гц на 50 мілісекунд, 1000 Гц на 80 мілісекунд та 800 Гц на 120 мілісекунд.
- **Локальна візуалізація на дисплеї:** Виведення на LCD 1602 імені власника картки, рішення ACCESS GRANTED, ACCESS DENIED, OFF-SHIFT NIGHT або ALERT CRITICAL та поточного режиму зміни.
- **Хмарний журнал і дистанційне керування Blynk:** Синхронізація 6 віртуальних каналів V0-V5 зі станом замка, іменем користувача, статусом допуску, індексом ризику, режимом зміни та висновком аудиту, а також дистанційне відмикання дверей черговим лікарем.
- **Термінальний журнал подій:** Запис кожної події у форматі `[хвилини:секунди] [КАТЕГОРІЯ] повідомлення` та виведення зведеної таблиці Status Table у консоль кожні 4 секунди.

## Апаратна частина Wokwi

| Компонент | Підключення | Призначення |
|---|---|---|
| ESP32-DevKitC-V4 | - | Головний мікроконтролер системи |
| Дисплей LCD 1602 I2C | SDA GPIO 21, SCL GPIO 22, VCC 3.3V, GND | Відображення імені пред'явника картки, рішення доступу та режиму зміни |
| Сервопривід | PWM GPIO 18, V+ 5V, GND | Переміщення ригеля дверного замка між закритим і відкритим положенням |
| Зелений світлодіод | GPIO 2 через резистор 220 Ом, катод GND | Індикація дозволеного проходу |
| Червоний світлодіод | GPIO 4 через резистор 220 Ом, катод GND | Індикація відмови у доступі та аварійного блокування |
| Резистори 220 Ом | Між GPIO та анодами світлодіодів | Струмообмежувальний захист ліній світлодіодів |
| П'єзоелектричний зумер | GPIO 27 через апаратний LEDC таймер, другий контакт GND | Звукове сповіщення про дозвіл, відмову та блокування |
| Зелена кнопка | GPIO 32, другий контакт GND | Імітація картки RFID чергового лікаря |
| Синя кнопка | GPIO 33, другий контакт GND | Імітація картки RFID медсестри денної зміни |
| Червона кнопка | GPIO 25, другий контакт GND | Імітація невідомої картки RFID сторонньої особи |
| Жовта кнопка | GPIO 26, другий контакт GND | Перемикання денної та нічної зміни |
| Макетна плата | - | Комутація ліній живлення 3.3V, 5V, землі та сигнальних провідників |

## Структура файлів

| Файл | Опис |
|---|---|
| `src/sketch.ino` | Основна логіка ESP32: опитування кнопок, сервопривід, дисплей, світлодіоди, зумер LEDC, Wi-Fi, Blynk, журнал подій та таблиця стану |
| `src/ai_security_audit.h` | Модуль AI-аудиту доступу: ролі, зміни, розрахунок індексу ризику, класифікація загроз, рішення доступу та захисне блокування |
| `diagram.json` | Схема підключення компонентів у симуляторі Wokwi |
| `platformio.ini` | Конфігурація проєкту для середовища PlatformIO |
| `libraries.txt` | Список залежностей та бібліотек для симулятора Wokwi |
| `wokwi.toml` | Файл налаштувань запуску симулятора Wokwi |

## Як запустити

1. Відкрити [симуляцію проєкту у Wokwi](https://wokwi.com/projects/477614933885999105) або проєкт у середовищі PlatformIO та вказати у `src/sketch.ino` власні `BLYNK_TEMPLATE_ID`, `BLYNK_TEMPLATE_NAME` і `BLYNK_AUTH_TOKEN`.
2. Скомпілювати прошивку командою PlatformIO Build.
3. Відкрити `diagram.json` та запустити симулятор Wokwi.
4. Відкрити Serial Monitor для спостереження за журналом подій та таблицею Status Table.
5. Натиснути зелену кнопку лікаря та переконатися у відкритті ригеля на 3 секунди із зеленою індикацією.
6. Перемкнути жовтою кнопкою нічну зміну та натиснути синю кнопку медсестри для перевірки відмови OFF-SHIFT NIGHT.
7. Натиснути червону кнопку невідомої картки 3 рази поспіль і перевірити перехід у режим LOCKOUT на 15 секунд.
8. Перевірити оновлення 6 віджетів на веб-панелі Blynk та дистанційне керування замком і зміною через канали V0 та V4.
